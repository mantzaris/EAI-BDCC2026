\section{A Typed Temporal Semantic Representation}
\label{sec:representation}

\subsection{Schema-Guided Ontology Instantiation}

The ontology is fixed in code; the generator proposes instances inside it.
Formally, let
\begin{equation}
\begin{split}
 \Omega&=(\mathcal T,\mathcal R,\operatorname{dom},\operatorname{ran},\mathcal C),\\
 G_t&=(V_t,E_t,\vartheta_V,\vartheta_E,a_t).
\end{split}
\label{eq:ontology}
\end{equation}
Here $\mathcal T$ and $\mathcal R$ are node and relation vocabularies;
$\vartheta_V:V_t\to\mathcal T$ and $\vartheta_E:E_t\to\mathcal R$ give their
types. An edge of type $r$ connects allowed types in $\operatorname{dom}(r)$ and
$\operatorname{ran}(r)$. Attributes $a_t$ include immutable and logical IDs,
dataset/subject/session scope, event intervals, ingestion time, version, value,
unit and evidence state. Constraints $\mathcal C$ include immutable identifiers,
finite acyclic declared dependencies and the admission predicates below.
Ingestion time is written $\tau_v$, distinct from the type maps $\vartheta$.
At knowledge time $t$, only records with $\tau_v\leq t$ are visible. Current
assessments use their recorded knowledge time for visibility. Current
queries resolve each logical identity to its greatest visible version, breaking
ties by ingestion time and ID; historical queries retain their specified
knowledge time.
Tied assessments retain their trigger IDs; conflicting states are marked ambiguous
because the stored timestamp alone does not order triggers.

Table~\ref{tab:objects} identifies stored objects. Windows carry hashes, sample
indices and channel metadata; raw arrays remain outside the database. Features
carry units, extractor metadata and source IDs. The \texttt{with\_entities}
function adds subject and channel identities. The model proposes proposition
fields, evidence references, parent links and sentences. Checks admit bounded
claims before immutable insertion. Neo4j additionally creates
\texttt{SupportAssessment} nodes and \texttt{ASSESSED\_AS} edges, included in
storage accounting. The Supplement specifies every node/relation's meaning,
domain/range, creation rule, provenance and status, including unresolved placeholders.

The construction can be written as
\begin{equation}
 G_t=\Gamma_\Omega(E_{\leq t},\widehat C_{\leq t})
 =\operatorname{Insert}_{\rm immutable}\!\left(
 \operatorname{Check}_q\!\left(\operatorname{Normalize}_\Omega(E_{\leq t}),
 \widehat C_{\leq t}\right)\right).
\label{eq:construction}
\end{equation}
$E_{\leq t}$ is the observation/revision log; $\widehat C_{\leq t}$ contains
model proposals generated from the normalized visible evidence. Rejected
proposals remain in the request archive. Inserted assessments and explanation
versions extend the instance without overwriting earlier content. This is
schema-guided instantiation, rather than ontology discovery.

Construction determines much of the apparent topology. Each \texttt{source\_ids}
entry creates dependent-to-input \texttt{DEPENDS\_ON}; features also receive
\texttt{DERIVED\_FROM}, and accepted claims the opposite-direction
\texttt{SUPPORTS} mirror. Display membership adds two relations:
\texttt{CONTAINS} and \texttt{DEPENDS\_ON}. Subject links create
\texttt{FOR\_SUBJECT} hubs.
We separate these administrative, provenance and reasoning roles.

\subsection{Edges as Explicit Semantic Commitments}

A citation identifies a proposed evidence witness. A parent link declares a
prerequisite. A deterministic extraction edge records how a feature was produced.
Membership and co-occurrence carry neither implication. In particular, an
LLM-proposed \texttt{DEPENDS\_ON} edge does not prove that its target is a necessary
premise. \texttt{SUPPORTS} records acceptance at insertion, not support at every
later time. A \texttt{CONTRADICTS} edge records an adverse assessment triggered by
a revision; its associated assessment supplies the knowledge time. Exports retain
these origins and the distinction between proposed, accepted and displayed links.

\subsection{The Query-Specific Semantic Core}

We define a projection rather than discover a second ontology:
\begin{equation}
 K_{q,t}=\pi_{q,\Omega}(G_t),\qquad
 V(K_{q,t})=C_{q,t}^{*}\cup F_{q,t},\quad
 E(K_{q,t})=D_{q,t}\cup P_{q,t}.
\label{eq:core}
\end{equation}
$C_{q,t}^{*}$ contains the latest displayed answer's member claims and their
declared claim ancestors. $F_{q,t}$ contains their visible cited feature
propositions, including explicit availability watches. $D_{q,t}$ retains the
corresponding stored dependency edges; $P_{q,t}$ contains labelled derived paths
that resolve an immutable citation through a visible version chain. Each derived
path retains its source citation and supersession witness IDs. It is never drawn
as a directly stored Neo4j relationship.

Subject/sensor identity, explanation containers, assessments and old versions are
sidecars. Feature-to-observation provenance is retained there and may be expanded
in a drawing. Claim scope comes from the asserted proposition fields, rather than
the storage wrapper's query interval. Full IDs, raw sentences, original versions
and assessment times remain recoverable. Thus the projection preserves the
explicit commitments needed for the answer and its revision; its smaller size
is a consequence of a specified selection rule.

We distinguish the complete stored graph, an active evidence-and-claim projection
at $t$, and $K_{q,t}$. The active projection includes latest evidence and current
display members across queries, retaining actual observation provenance. The
core answers more focused competency questions: which window supports a value,
which operands support a comparison, which version was known, what changed after
correction, and whether an alternative witness survives. We evaluate answers to
these questions against immutable input logs or exact program specifications,
independently of database support flags.
